# Tauri 2 ↔ TS 타입 안전 IPC (specta / tauri-specta)

work-radar의 IPC는 Rust 타입에서 TS를 **생성**한다. 수기 TS 타입 중복은 금지(INVARIANT).

## 버전 핀 (Tauri 2 호환 라인은 RC뿐)
- `specta = "=2.0.0-rc.25"` (features: derive)
- `specta-typescript = "0.0.12"`
- `tauri-specta = "=2.0.0-rc.25"` (features: derive, typescript)

세 크레이트는 RC 라인이 정확히 맞아야 한다. 임의 업그레이드 금지(깨짐).

## 단일 레지스트리 (src-tauri/src/lib.rs)
새 command/event는 **반드시** 공유 빌더에 추가한다 — `run()`과 export 테스트가 같은 빌더를 쓴다:

```rust
pub fn tauri_specta_builder() -> SpectaBuilder<tauri::Wry> {
    SpectaBuilder::<tauri::Wry>::new()
        .commands(collect_commands![commands::list_projects /* , 새 command 추가 */])
    // 이벤트는 .events(collect_events![...]) + setup에서 builder.mount_events(app)
}
```

## Command 작성 패턴 (src-tauri/src/commands.rs)
```rust
#[tauri::command]
#[specta::specta]
pub async fn list_projects(db: State<'_, Db>) -> Result<Vec<Project>, String> {
    fetch_projects(db.inner()).await.map_err(|e| e.to_string())
}
```
- 반환 타입/인자 타입은 `serde` + `specta::Type` 파생 필요(`Project` 등 models.rs).
- 에러는 `Result<_, String>`로 **그대로 노출**(terminal failure 삼키지 않음 — INVARIANT). 프런트는 error를 throw.
- 외부 호출(Notion/GitHub)은 command(=Rust) 안에서. 토큰을 렌더러로 보내지 않는다.

## 바인딩 생성 (src/bindings.ts)
- export 경로: `../src/bindings.ts` (`#[cfg(any(debug_assertions, test))]`에서만).
- **재생성 = `cargo test`** — `bindings_export::export_typescript_bindings` 테스트가 생성한다. dev 런타임도 debug 빌드에서 export.
- `src/bindings.ts`는 **저장소에 커밋**(프런트 빌드가 Rust 실행 없이 성립). **절대 손으로 편집하지 말 것** — 파일 상단 "Do not edit this file manually."
- 프런트는 `@/bindings`에서 import (타입드 command 호출).

## Capabilities / Permissions
- 창/플러그인 권한은 `src-tauri/capabilities/default.json`에 선언(global-shortcut, window 등). 새 플러그인 쓰면 권한 추가.

## 검증
- `cargo test` — 바인딩 재생성 + export 테스트 green.
- `pnpm typecheck` — 생성된 bindings.ts가 프런트와 정합.
- 명령 인덱스: `docs/reference/commands.md`.
