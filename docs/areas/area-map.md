# Area Map

Use this map to decide, BEFORE opening any file:

1. Which **domain** does the change touch? (file glob in column 2)
2. Which **docs** must be loaded for that domain? (column 3 = required, column 4 = forbidden-when-only-this-domain)
3. Which **verification** path applies? (column 5)

The thin `CLAUDE.md` at the repo root mirrors this table as one-liners and tells the agent:
"Load only the rows your scope intersects."

## Why this exists

Today every agent session loads `CLAUDE.md` (thin) + `AGENTS.md` (~65 lines, inlines shadcn/news/tech-stack) + `PLAN.md` (heavy: INVARIANTS § + 20 Phases). An agent fixing a news fetcher bug loads shadcn migration discipline; an agent rewriting `MatrixCanvas` loads SQLite migration rules. Auto-memory shows recurring incidents (parallel-worktree contamination, executor-late-writes, loop-shares-tree, rtk pipe truncation, shadcn keep-vs-migrate misjudgments) where the relevant rule was buried — or absent.

Goal: **load the rule only when the scope says you need it.**

## How `CLAUDE.md` uses this map

`CLAUDE.md` is the entry point. It contains:

- `@AGENTS.md` (auto-load)
- A short list of routing lines, one per domain, of the form
  "When touching `<glob>`, also read `docs/areas/<area>.md`."
- Pointer to `docs/reference/commands.md`, `DESIGN.md`, `PLAN.md` (Phase).
- Pointer back to this `area-map.md` for the authoritative table.

`AGENTS.md` is the durable working agreement only. It contains rules that apply
to **every** domain (verification posture, PR shape, forbidden shortcuts, etc.).
Domain-specific discipline (shadcn keep-vs-migrate, RSS feed parsing, Esc
contract on modals) lives in `docs/areas/<area>.md` and is loaded only when the
file glob says it's needed.
