# G2-PR2 — Batch Apply/Remove (Ephemeral Presets) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user multi-select managed skills and apply/remove them to their agent dirs in one best-effort action, reporting a per-item outcome.

**Architecture:** Pure composition over G2-PR1. Two new Rust batch cores (`apply_batch_core`/`unapply_batch_core`) loop the existing single `apply_core`/`unapply_core` and classify each `Result` into a `BatchItemResult`; two thin IPC commands wrap them. No migration, no new persisted state — applied state stays disk-derived (INVARIANT #7), audit stays per-item inside the single cores (rail ①), zero job spawn (#1/#2). The frontend **extends the existing multi-select batch bar** (`SkillsView.tsx` + `src/lib/skillBatch.ts`) rather than adding a parallel selection system.

**Tech Stack:** Rust (Tauri 2, sqlx, specta/tauri-specta), React + TanStack Query, shadcn/ui, vitest.

**Spec:** `docs/superpowers/specs/2026-06-01-skills-manager-g2-pr2-presets-design.md`

- Rust gates run from `src-tauri/` after `export PATH="$HOME/.cargo/bin:$PATH"`.
- `cargo test` regenerates `src/bindings.ts` (no GUI boot). Bindings drift is a CI gate.

```rust
/// `roots`에서 provider의 외부 루트를 찾는다(provider_segment 동치). 미지원이면 None.
fn find_root(roots: &[(SkillProvider, PathBuf)], provider: SkillProvider) -> Option<&Path> {
    let want = provider_segment(provider);
    roots
        .iter()
        .find(|(p, _)| provider_segment(*p) == want)
        .map(|(_, path)| path.as_path())
}

fn item_result(item: &SkillRef, outcome: BatchOutcome, message: Option<String>) -> BatchItemResult {
    BatchItemResult {
        provider: item.provider,
        name: item.name.clone(),
        outcome,
        message,
    }
}

/// core: 배치 적용. 각 항목을 독립 처리(best-effort) — 한 항목 실패가 배치를 중단시키지 않는다.
/// 변이는 단일 `apply_core`에 위임하고 그 `Result`만 outcome으로 분류한다(변이 로직 단일 소스).
pub(crate) async fn apply_batch_core(
    pool: &SqlitePool,
    central_root: &Path,
    roots: &[(SkillProvider, PathBuf)],
    items: &[SkillRef],
) -> Vec<BatchItemResult> {
    let mut out = Vec::with_capacity(items.len());
    for item in items {
        let res = match find_root(roots, item.provider) {
            None => item_result(item, BatchOutcome::UnsupportedProvider, None),
            Some(ext_root) => {
                match apply_core(pool, central_root, ext_root, item.provider, &item.name).await {
                    Ok(_) => item_result(item, BatchOutcome::Applied, None),
                    Err(e) => match e.code.as_str() {
                        CODE_COLLISION => item_result(item, BatchOutcome::Collision, None),
                        CODE_NO_SOURCE => item_result(item, BatchOutcome::NoSource, None),
                        _ => item_result(item, BatchOutcome::Error, Some(e.message)),
                    },
                }
            }
        };
        out.push(res);
    }
    out
}
```

/** best-effort 배치 결과를 사람용 한 줄 요약으로. 0건 카테고리는 생략. 빈 결과 → null. */
export function summarizeBatch(results: BatchItemResult[]): string | null {
  if (results.length === 0) return null;
  const label: Record<BatchItemResult["outcome"], string> = {
